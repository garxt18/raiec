RAIEC INTERNSHIP PROJECT REPORT - PART 7: WORKFLOW STAGE 3

STAGE 3: RATE MATCHING ENGINE

FRONTEND (step3-rate-match.html):
- POST to /api/tenders/{id}/rate-match
- Show loading spinner

BACKEND ALGORITHM (RateMatchService.evaluate):
For each ScheduleEntry:

1. Determine Reference: SCHEDULED → DSR/IRUSSOR, NON_SCHEDULED → LAR

2. Exact Code Match: Query by itemCode + edition

3. Fuzzy Description Match (if no code match):
   - Normalize: lowercase, remove special chars
   - Generate trigrams: "cement" → ["cem","eme","men","ent"]
   - Calculate similarity: intersection / union
   - Threshold: > 0.60 (60%)

4. Calculate Variance:
   variance = ((quoted - reference) / reference) × 100

5. Apply Thresholds:
   ≤ 0%: OK
   0-5%: OK
   5-10%: WARN
   >10%: FAIL

6. Build Response: itemCode, description, rates, variance, verdict

FRONTEND RENDERING:
- Color-coded table: Green (OK), Yellow (WARN), Red (FAIL)
- Reference source badges (DSR/IRUSSOR/LAR)
- Variance percentages
- Summary: "45 OK, 3 WARN, 2 FAIL"

TECHNOLOGIES:
Custom Trigram Algorithm, Spring Data JPA, BigDecimal, CSS Flexbox
